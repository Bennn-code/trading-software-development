# 電子郵件註冊設定

網站已備妥「電子郵件＋自訂密碼 → 寄送驗證碼 → 輸入驗證碼 → 登入」流程。沒有設定服務時，註冊按鈕會停用，並明確顯示尚未啟用，不會假裝已寄出信件。

## 1. 建立 Supabase 專案

1. 前往 [Supabase Dashboard](https://supabase.com/dashboard)，註冊並建立新專案。
2. 專案名稱可用 `trade-journal`。資料庫密碼自行保存在密碼管理器，網站不需要這個密碼。
3. 在專案的 **Connect / API Keys** 設定找到 Project URL 及 **Publishable key**。只使用 publishable key，不需要 `service_role` 或 secret key。
4. 在網站的執行環境設定加入 `SUPABASE_URL`、`SUPABASE_PUBLISHABLE_KEY`。本機開發放 `.env`；正式網站須另設 Sites 執行環境變數，再部署更新。

## 2. 開啟電子郵件及驗證

在 **Authentication → Sign In / Providers → Email**：

- 啟用 Email 註冊、**Confirm email**；不能關閉驗證。本網站偵測到註冊直接建立登入階段時會拒絕完成註冊。
- 建議密碼最少 12 字元，與網站一致。
- 設定 Email OTP 的有效期間，例如 10 分鐘；長度使用 6 至 8 位數，網站皆可接受。
- 保留服務端的寄信、登入與驗證速率限制。網站另提供 60 秒重寄倒數，但安全限制由 Supabase 服務端執行。

在 **Authentication → URL Configuration** 將 Site URL 設為：

`https://trade-notes-benjamin.beeennnkkk.chatgpt.site`

## 3. 確認信改成驗證碼

在 **Authentication → Email Templates → Confirm signup**，使用下列 HTML。務必保留 `{{ .Token }}`，它才是使用者要輸入的驗證碼。

```html
<h2>交易手記｜電子郵件驗證 / Verify your email</h2>
<p>請回到交易手記，輸入下方驗證碼完成註冊。</p>
<p>请返回交易手记，输入下方验证码完成注册。</p>
<p>Return to Trade Journal and enter this code to finish signing up.</p>
<p style="font-size:32px;letter-spacing:6px;font-weight:bold">{{ .Token }}</p>
<p>如果不是你申請，請忽略此信。If you did not sign up, ignore this email.</p>
```

可直接使用 [確認信 HTML 範本](../supabase/templates/confirmation.html)。網站使用 Supabase 的 `verifyOtp` 驗證，不自行產生或儲存密碼與驗證碼。

## 4. 寄信服務

Supabase 的預設寄信服務只適合測試，限制收件者及頻率。要讓一般使用者註冊，須到 **Authentication → Email / SMTP Settings** 設定自己的 SMTP 寄信服務與已驗證寄件地址。SMTP 密碼只填在 Supabase，不需要放進本網站。

官方文件：[電子郵件範本](https://supabase.com/docs/guides/auth/auth-email-templates)、[SMTP](https://supabase.com/docs/guides/auth/auth-smtp)、[速率限制](https://supabase.com/docs/guides/auth/rate-limits)。

## 5. 驗收與原有紀錄

1. 使用自己的信箱註冊，設定密碼；確認驗證前無法登入。
2. 實際收到信後輸入錯誤碼、正確碼，測試重寄及過期情況。
3. 登出，再使用設定的密碼登入；新增一筆測試交易。
4. 使用另一個測試帳號，確認看不到第一個帳號的交易及圖片。
5. 原有 ChatGPT 交易空間不會自動合併。若需要連結，在同一瀏覽器登入原本 ChatGPT 身分及新的已驗證電子郵件帳號，在「我的交易空間」勾選確認後連結。電子郵件空間必須沒有交易、圖片或心得，避免把已有紀錄隱藏。
6. 切換語言並重新整理，確認選項保存。已有帳號時會同步帳號偏好；未登入時只存此瀏覽器。

目前 Sites 仍維持原本的私人存取權限。獨立電子郵件帳號不會繞過 Sites 外層權限；需要讓其他人使用時，應在寄信及帳號隔離驗收完成後，再由擁有者調整網站分享範圍。

目前沒有忘記密碼的自助重設畫面。正式對外開放前，應補上並測試密碼重設流程。

## 開發驗證

- `node tests/account.test.mjs`：真實 Supabase SSR 用戶端搭配本機模擬驗證服務、記憶體資料庫；涵蓋驗證碼、重寄、Cookie、登入登出、跨站請求、帳號隔離與連結。**不代表實際郵件已送達。**
- `node tests/language.test.mjs`：翻譯、日期標籤、插值與字典完整度。
- `node tests/account.integration.mjs`：未配置服務時正式路由安全關閉、舊登入及語言偏好保存。

登入狀態放在 HttpOnly、SameSite Cookie；HTTPS 正式環境加上 Secure。所有資料路由在伺服器向 Supabase 查證使用者，而不是直接相信 Cookie 內的使用者資訊。權限仍由每筆資料的 `user_id` 控制。
