# 網站安全部署檢查

本站的安全防護分為應用程式程式碼與託管服務設定。程式碼不能替代 Cloudflare、Supabase、GitHub 等服務帳號的安全設定，也不能保證網站永遠不會遭受攻擊。

## 必須設定的人機驗證

在正式環境設定以下兩個 Cloudflare Turnstile 值：

- `TURNSTILE_SITE_KEY`：公開站台金鑰，前端用來顯示人機驗證。
- `TURNSTILE_SECRET_KEY`：私密伺服器金鑰，只能設在託管環境的 Secret／環境變數中，不可提交到 GitHub、前端程式或聊天記錄。

兩者須屬於同一個 Turnstile Widget，並包含正式網站網域。缺少任一值時，註冊、登入、重新寄送驗證信與忘記密碼請求會安全地回覆服務尚未設定，而不會略過人機驗證。部署前必須在正式託管環境設定並測試這兩個值；本機 `.env.example` 只有空白範例。

## Cloudflare

- 確認正式網站流量經 Cloudflare 代理，並啟用適用於網域的託管 WAF／DDoS 規則。
- 在分析頁檢查驗證挑戰、被封鎖請求和 4xx／5xx 峰值；先觀察誤判，再調整自訂規則。
- 網站目前回傳含 `includeSubDomains` 的 HSTS。確保主網域與所有子網域都使用 HTTPS，再保留這項政策。
- 對 Cloudflare 帳號啟用 MFA，限制 API Token 權限；部署憑證只存於託管平台的 Secret 設定。

## Supabase 與登入

- 保持電子郵件驗證啟用，並將 Site URL 與 Redirect URL 限定為正式站及必要的測試站。
- Supabase `service_role` 金鑰只能放在伺服器端 Secret；不得放入瀏覽器、公開設定或 Git 儲存庫。
- 對 Supabase、Cloudflare、GitHub 與寄信服務的管理帳號啟用 MFA。若 Supabase 方案支援外洩密碼檢查，可在 Auth 設定中啟用。
- Turnstile、登入失敗、驗證信與忘記密碼操作均須以正式網域測試，確認密鑰錯誤或驗證服務逾時時有清楚的暫時失敗訊息。

## 備份、告警與程式依賴

- 確認正式 D1 資料庫的時間點復原／備份方案，並定期實際演練還原；交易資料與 R2 截圖需一起納入復原計畫。
- 設定登入失敗、速率限制、AI／寄信用量、資料庫錯誤與部署失敗告警。安全事件日誌不可包含密碼、Cookie、OTP、API Secret 或完整交易內容。
- 在 GitHub 啟用 Dependabot alerts、密鑰掃描及適用的程式碼掃描；高風險依賴更新須先測試再部署。
- 交易所金鑰應在交易所端設為唯讀，關閉下單、提款與轉帳權限；支援時限制 IP。本站連線器只呼叫預設交易所的查詢端點，但這不取代交易所端權限限制。

## 發布前操作測試

至少測試註冊、登入、驗證碼、忘記密碼、登出、交易新增／修改／刪除、截圖上傳與辨識、CSV／Excel 匯入、API 匯入、心得儲存、資料匯出及帳號註銷。安全標頭的調整應先在測試環境檢查登入元件、圖表、匯入和手機版，再逐步加嚴。
